# 技能内容与打包

> 计划位置：第 1 个（共 2 个）；前置：无；后继：20261121-唐启云-技能门禁与文档

## 背景

- 技能只用于“第一次给项目初始化 swagger2api 配置”这类低频场景；日常生成只跑脚本，不需要常驻、不需要安装、不需要薄壳。
- 技能随 npm 包发布即可：升级依赖即升级技能；使用时由 AI 主动读取包内入口。
- 为让 AI 能稳定定位，提供一个只读的定位命令，不写文件、不维护状态。

## 实施方案

1. **目录与命名**：新增 `skills/fxri-swagger2api/SKILL.md`（入口）与 `skills/fxri-swagger2api/references/`（配置决策、CLI 参数、产物结构、迁移流程各一篇）；目录名用小写 kebab 且沿用 `fxri-` 前缀；`package.json` 的 `files` 增加 `skills`。
2. **入口内容**：frontmatter 与既有技能集对齐（`name` / `description` / `license` / `metadata.version` / `tier` / `triggers` / `author` / `source`），版本**独立于包版本**，仅在技能内容变更时递增（与既有技能集一致，避免工具与技能互相牵动版本）；版本行沿用「本技能版本 x（随 @fxri/swagger2api 分发）。被问版本时即报此值；与已安装依赖的技能版本不一致即说明会话上下文已过期」；章节骨架沿用「何时使用 / 工作流 / 不做 / 参考」。
3. **正文要点**：何时使用（首次初始化配置、迁移旧配置、调整产物结构；日常生成不加载）、最小配置怎么定（`mode` / `client` / `language` / `responses` / `query` / `pathPrefixIndex` / `tagRewrite`）、先 `--dry-run --json` 预览再落盘、产物结构（`index` / `client` / `types/`）、粒度由工具按接口量决定、禁止手改生成物、验收命令。
4. **篇幅**：入口建议 150 行内，硬上限与 toolkit 预算一致（200 行 / 12000 字符）；决策表与参数细节下沉 `references/`，避免 AI 一次读入过量。
5. **定位命令**：`swagger2api skill` 输出包内技能入口的绝对路径；`--print` 输出入口内容；`--json` 输出 `{ entry, referencesDir, version }`。只读、幂等、不写文件；包内路径由包根解析，兼容本地与全局安装、含空格的路径。
6. **自描述（可选）**：`package.json` 增加 `"agentSkills": "./skills"` 仅作声明，不实现任何发现/安装逻辑。
7. **版本递增**：`skills/**` 有改动时同批递增技能 `metadata.version`，优先用 `toolkit skills bump --dir skills --all patch` 写回两处；工具不可用时手动改，并由门禁兜底；不因包版本变化而空增。
8. **变更集**：patch 变更集，说明发布物新增技能目录与定位命令。

## 影响范围

- `skills/fxri-swagger2api/SKILL.md`、`skills/fxri-swagger2api/references/`
- `src/commands.ts`、`src/cli.ts`（新增 `skill` 子命令与帮助）
- `package.json`（`files` 白名单、可选 `agentSkills` 声明）
- `src/__tests__/`（定位命令输出）
- `.changeset/`

## 验证方式

- `pnpm build && npm pack --dry-run` 的产物列表包含 `skills/fxri-swagger2api/**`。
- `swagger2api skill` 在仓库根、任意子目录与含空格的路径下都输出存在的入口路径；`--print` 输出内容含 frontmatter；`--json` 三段键齐全且 `entry` 可读。
- 目录名为小写 kebab；frontmatter 必填字段齐全；references 均可解析；入口不超过 150 行。
- 技能版本与包版本互不绑定：只改包不改技能时不要求递增；`skills/**` 有改动时版本必须递增。
- `pnpm verify` 全量通过。
- 回滚：移除技能目录与命令即回到现状，不影响生成链路。
