# 内置后处理与产物校验

> 计划位置：第 2 个（共 3 个）；前置：20261121-唐启云-多目标配置与批量校验；后继：20261121-唐启云-接口面基线命令

## 背景

- 业务仓为去掉生成物的 `// @ts-nocheck`，各自写包装脚本生成后再删一行；这又导致内置 `--check` 与真实产物不一致，只能再写一套临时目录比对。
- 后处理是工具职责：生成与校验必须走同一管线，业务仓不再维护剥离脚本。

## 实施方案

1. **配置**：新增 `typeCheck`（扁平配置）/ `output.typeCheck`（嵌套配置）同义字段，取值 `skip`（默认，保留 `@ts-nocheck`）/ `enforce`（不写或剥离该行）。
2. **生成管线**：按配置在写盘后、写清单前完成处理；TS / JS 模式同时处理 `.ts` / `.js` / `.d.ts`；`--check` 生成临时产物时执行同一处理后再比对。
3. **兼容**：默认 `skip` 保持现有行为；单文件 / 分组模式一致；`--dry-run` 不写盘。
4. **测试**：`enforce` 下产物无 `@ts-nocheck`；`--check` 通过；默认不回归；JS 模式声明文件同样处理。
5. **文档**：`docs/config.md`、`docs/cli.md`、`skills/fxri-swagger2api/references/output.md`。
6. **变更集与版本**：patch，目标版本 **1.3.2**；条目按「修复」书写；技能 references 变更时递增 `fxri-swagger2api` 技能版本；不单独发版，与其余工具任务一起发 1.3.2。

## 影响范围

- 生成入口与 `--check` 比对流程（`src/index.ts`）
- 产物模板或后处理工具函数
- 测试、文档、技能 references、`.changeset/`

## 验证方式

- `typeCheck: "enforce"` 的仓生成后无 `@ts-nocheck`，`--check` 通过。
- 默认 `skip` 的仓产物与现状一致。
- `pnpm verify` 全量通过。

## 回滚

移除配置项与处理分支，恢复默认保留；`--check` 回到原比对口径。
