# AI 诊断能力与技能对齐

> 计划位置：第 3 个（共 3 个）；前置：20261121-唐启云-移除产物清单改按横幅清理、20261121-唐启云-新增显式清理命令；后继：无

## 背景

- 工具随包分发 AI 技能，AI 按技能文档决定「下一步跑什么命令」。本次清理口径从清单改为横幅、并新增清理命令，如果技能不更新，AI 会继续按「清单」心智操作。
- 现有诊断输出以人读文本为主：`--check` 没有结构化结果，清理命令没有机器可读清单，AI 只能靠正则猜结论，容易误判。
- 破坏性操作缺少面向 AI 的护栏说明（如清理默认 dry-run、`--yes` 才执行）。

## 实施方案

1. **技能文档对齐**：
   - `references/output.md`：删除「清单写入系统临时目录」表述，写明「生成物靠横幅归属、手写文件不带横幅」与 `output.prune` 语义；
   - `references/config.md`：补 `output.prune` 的行为与默认值；
   - `references/cli.md`：补 `--check --json`、`inspect --json`、`prune --dir [--json]` 与退出码表（0 通过 / 1 校验失败 / 2 参数或配置错误）。
2. **AI 排障手册**（新增小节，症状 → 命令）：产物多余 / 过期 / 缺失 / 配置冲突 / 模式切换，统一给出只读优先命令与预期输出；明确 AI 不得自行追加 `--yes`，需用户确认。
3. **使用顺序改写**：生成 → `--check`（可 `--json`）→ `inspect --dir` → 仅废弃目录用 `prune --dir`；并写入「生成后必须跑 `--check`，失败不改产物，按提示重跑或清理」。
4. **结构化输出约定**：三个诊断命令的 `--json` 统一带 `schemaVersion`、`toolVersion`、分类清单（missing / mismatched / extra）、稳定错误码（如 `E_CONFIG_CONFLICT`）与 `actions`（建议的下一步命令，给出可直接复制的完整命令）；技能里附一张字段表，AI 复用同一套解析逻辑；JSON 模式下人类日志走 stderr，保证 stdout 可解析。
5. **双用途**：同一份 JSON 同时服务 AI 决策与 CI 摘要（GitLab/GitHub 注解），文档写明两者共用一份输出，不另设 CI 专用格式。
6. 技能版本经 `toolkit skills bump` 递增（能力级改动），文档站与 SKILL.md 同步；排障手册放 `references/`，SKILL.md 只留入口与「生成后必跑 `--check`」，控制技能体积。

## 影响范围

- `skills/fxri-swagger2api/SKILL.md` 与 `references/{cli,config,output}.md`、`docs/cli.md`、技能版本与变更集（patch）。
- 不改生成逻辑；依赖任务 1、2 的命令与输出形态。

## 验证方式

- `toolkit skills lint` 与 `toolkit skills bump` 正常；`pnpm verify` 技能打包与入口断言通过。
- 按排障手册逐条走一遍「症状 → 命令 → 输出 → 下一步」，确认 AI 可仅凭 JSON 与结论行决策。
- `--json` 输出可被 `JSON.parse` 直接解析，stdout 无人类日志混入；字节为 UTF-8 无 BOM，断言含 `toolVersion` 与错误码。

## 回滚方案

还原技能与文档、递增后的版本与变更集；不影响命令行为。
