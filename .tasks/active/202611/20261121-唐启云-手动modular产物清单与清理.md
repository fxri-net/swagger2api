# 手动 modular 产物清单与清理

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

- 通过 `--modular` 手动开启分离文件时没有分组命名表，生成后不写产物清单；重复生成或调整分组后，旧模块与旧 `types/` 文件会残留。
- `--check` 目前只覆盖有清单的分组模式，手动模式无法发现表外产物，容易把过期文件带进下游类型检查。

## 实施方案

1. **清单覆盖手动模式**：手动 `--modular` 生成完成后同样写清单，文件集为 `index` / `client` / `types/**` / `route-types` 与实际存在的模块文件（含 JS 模式的 `.d.ts`）。
2. **复用现有能力**：清理、手写文件护栏、表外检查在命名表为空时以扫描结果为基准；仍只删除“在上一轮清单内、本轮不再生成”的文件，不清空目录。
3. **`--check` 对齐**：手动模式下校验清单与磁盘产物一致，缺文件或出现表外模块文件都判失败并列出文件名。
4. **清单形态不变**：只记文件名与子路径，不写工具版本；仍落在系统临时目录。
5. **文档与变更集**：`docs/guide.md` 补一句手动模式同样受清单管理；patch 变更集。

## 影响范围

- `src/index.ts`（手动 modular 分支写清单与校验）
- `src/utils/modular.ts`（无命名表时的文件集收集与校验）
- `src/__tests__/modular.test.ts`
- `docs/guide.md`、`.changeset/`

## 验证方式

- 手动 `--modular` 连续生成两次，第二次删除一个分组后旧模块文件被清理。
- 手写文件不在清单内时不被删除，护栏照常报冲突。
- `--check` 在缺文件与多文件两种情况下都失败并给出文件名。
- TS 与 JS 两种模式均通过；`pnpm verify` 全量通过。

## 回滚

仅影响手动 modular 分支的清单写入与校验，回退即恢复现状；分组模式行为不变。
