# 模块化输出支持

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 搁置

- 搁置原因：用户主动暂缓，优先处理其它任务，尚未开始实施
- 重启条件：用户明确排期，或下游项目确认需要「一次生成即分组」时恢复
- 进度锚点：方案已定稿并落档，见下方「实施方案」与「方案口径」；代码零改动
- 搁置日期：2026-11-20

## 背景

- 现状：`--modular` 已透传给底层生成器，但本工具模板仍遍历全局 `routes.combined`，实测每个模块文件都包含全部接口（约 1,968 个），产物膨胀约 17 倍，等于不可用。
- 底层生成器的 modular 模式本身正常：直连实测可拆出 18 个文件，单文件最大 406 KB、总量 842 KB（单文件模式 977 KB）。
- 本工具的自定义 `http-client.ejs` 已自带完整 `HttpClient`，模块化可复用；差距只在 `api.ejs` / `route-types.ejs` 未按当前模块渲染，且模块文件缺少必要 import。
- 下游项目需要「`pnpm api` 一次生成即分组」，不接受生成后再人工拆分或后处理脚本。

## 实施方案

1. `src/templates/api.ejs`：新增 `config.modular` 分支，按 `it.route.moduleName` 生成类名、只遍历 `it.route.routes` 渲染 `procedure-call.ejs`；补齐 `HttpClient` / `RequestParams` / `ContentType` / `data-contracts` 与 axios 类型导入；与 `config.apiClassName` 撞名时类名追加 `Module` 后缀（`/api` 前缀会与根 `Api` 撞名）。非模块化分支保持原样。
2. `src/templates/route-types.ejs`：新增 `config.modular` 分支，按当前模块输出 `export namespace <Module>`，只遍历 `it.route.routes`。非模块化分支保持原样。
3. `src/index.ts`：`generateApi` 返回后判断 modular，基于返回值中的文件清单生成根聚合入口——TS 模式写 `index.ts`，JS 模式写 `index.js` + `index.d.ts`（受 `--remove-dts` 控制）；内容为逐模块 `import`、camelCase 模块属性、`set instance` 逐模块下发共享 axios 实例，并 `export * from "./data-contracts"`，保持单文件模式下 `new Api()` + `.instance` 的调用面不变。
4. `src/index.ts`：模块化时修正末尾完成提示（改为根入口 + 模块数量），并在文档中建议配合 `--clean-output` 防止前缀消失后残留旧模块文件。
5. 测试：新增本地 fixture（3 个前缀，覆盖 GET/POST、query、body、枚举），覆盖 modular + TS、modular + `--js`、`/api` 撞名、非 modular 回归四类用例。
6. 文档与变更集：`docs/cli.md` 补 modular 相关参数与根入口说明，`docs/guide.md` 新增「模块化输出」一节，`README.md` 能力矩阵补一行；`.changeset/` 新建 minor 变更集。

### 方案口径（默认按此执行）

- `/api` 撞名：模块类名加 `Module` 后缀，聚合入口按原名引用。
- 根聚合入口：默认生成，不额外提供关闭开关。
- 分组粒度：沿用底层生成器的路径首段（当前 16 组），暂不合并小前缀。

## 影响范围

- 仅影响 `--modular` 路径；非模块化输出须零变化（用回归用例兜底）。
- 新增公开约定：模块文件名/类名取自路径首段；`/api` 撞名规则；根入口的 `Api` 结构与 `instance` 可写行为。
- 下游项目接入方式：升级依赖后，在生成脚本追加 `--modular --module-name-index 0 --clean-output`，并同步其接口接入规范中的调用形态说明。
- 文档触达：docs/cli.md、docs/guide.md、README.md

## 验证方式

- `pnpm install` 后执行 `pnpm verify`（聚合门禁：typecheck / test / lint）。
- 用真实文档在临时目录生成一次，断言模块路由数（App 219、Home 943、Api 39）与根入口可被实例化。
- 非模块化模式生成一次并与现有产物比对，确认无差异。
