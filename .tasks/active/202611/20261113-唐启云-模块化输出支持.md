# 模块化输出支持

> 计划位置：第 2 个（共 2 个）；前置：20261113-唐启云-配置与交互式CLI；后继：无

## 背景

- 需求源头：下游姊妹仓的前端项目 swagger 文档极大。实测其生成产物为单文件 `index.js` 约 976 KB、`index.d.ts` 约 1.2 MB，导致 IDE / TS Server 卡顿、单次生成 diff 巨大、多人协作互相冲突。
- 当前形态：本工具已在单文件内按路径首段分组（`routes.combined` 渲染成 `class Api` 上的对象属性），业务侧以 `request.swagger.<组>.<方法>` 调用，出口只有一个。
- 目标：分组升级为「多文件 + 单一出口」，分组依据可配置、可交互建设、可复现；调用面形态保持不变。
- 与前置任务的关系：配置层（rc 三层、`--config` / `--profile`、`init` 向导、`config status`）由 20261113-唐启云-配置与交互式CLI 承担；本任务在 `grouping` 段之上实现分组逻辑与产物拆分。
- 分组口径：按 tag、按路径段、按自定义规则都是可选项，由用户在配置里选择，工具不替用户决定默认业务语义。

## 前置调研结论（已实测）

- `swagger-typescript-api@13.0.28` 的模块化模板上下文为 `route = { moduleName, routes }`；模板解析顺序为「自定义目录 → `templates/modular` → `templates/default`」，因此在本仓 `src/templates/modular/` 下新增同名模板即可覆盖，无需改依赖。
- 当前 `src/templates/api.ejs` 遍历全局 `routes.combined`，模块化时每个模块文件都会渲染全部接口（产物膨胀约 17 倍的成因）。
- 下游项目 `base/src/api/base/index.d.ts` 中 `class Api` 的成员是按路径首段生成的对象（`admin`、`home` 等），业务调用形如 `request.swagger.home.taxPdfRecalcPost`；拆分后必须保持该调用形态。
- 安全加固后的路径转义对正常路径零影响，模块名取自路径首段不受影响。
- 待执行时确认：13.0.28 是否提供 `config.fileNames.httpClient` / `dataContracts`（官方模块模板用到）；`generateApi` 返回值是否带文件清单（否则聚合入口改读输出目录）。

## 实施方案

### A. 分组策略（声明式 + 可交互建设）

1. 策略项：`tag`、`path`（路径段 + 深度）、`rules`（路径前缀 / 正则 / tag / operationId 匹配）、兜底组 `fallback`。
2. 优先级可配置，默认「显式规则 > tag > 路径段 > 兜底」；冲突在报表提示，不静默覆盖。
3. 阈值：低于 `minRoutes` 合并到父组或兜底组；超过 `maxRoutes` 按下一段路径或 tag 二次拆分。
4. 组名规范化：pascalCase、非法字符与 Windows 保留名检测、大小写冲突检测；与聚合类撞名（如 `Api`）加 `Module` 后缀。
5. 交互入口：`swagger2api grouping` 先输出统计（按 tag / 路径前缀的路由数与体积）→ 选择策略与优先级 → 合并小模块 / 拆分大模块 / 重命名 → 实时预览 → 写回配置的 `grouping` 段。
6. `--dry-run` 输出分组报表：组名、路由数、预估字节、未命中规则清单、新增 / 删除文件；`--json` 输出结构化结果。

### B. 产物结构（多文件 + 单一出口）

1. `output.mode = grouped` 时输出：`index.ts`（聚合入口）、`data-contracts.ts`、`http-client.ts`、每模块一个文件。
2. 聚合入口保持现有调用形态：按组名挂载模块实例，业务侧仍是 `request.swagger.<组>.<方法>`；`export * from "./data-contracts"` 供类型引用。
3. 模块文件只含该组接口；`language = js` 时聚合入口产出 `index.js` + `index.d.ts`；`output.clean` 配合报表处理增删。
4. `output.mode = single` 保持零变化（回归用例兜底）。

### C. 模板

1. 新增 `src/templates/modular/api.ejs`、`src/templates/modular/route-types.ejs`：按 `it.route.moduleName` 生成类名与命名空间，只遍历 `it.route.routes`。
2. 补齐模块文件所需 import（`HttpClient`、`RequestParams`、`ContentType`、`data-contracts` 与 axios 类型）。
3. 模板内保留安全加固后的既有渲染逻辑，避免与路径转义重复处理。

### D. 测试、文档与变更集

1. 夹具：复用 `fixtures/swagger.json`（3 前缀）覆盖 tag / 路径段 / 显式规则 / 阈值合并四类分组；新增「同 tag 跨前缀」「规则冲突」用例。
2. 分组用例：策略优先级、阈值合并与二次拆分、组名规范化与撞名后缀、`--dry-run` 报表内容、`--json` 结构。
3. 真实文档验证：下游项目文档生成后断言各组路由数与聚合入口可实例化，调用形态与现状一致。
4. 文档：`docs/guide.md` 新增「分组」章节（策略、优先级、报表），`docs/cli.md` 补 `grouping` 与报表参数，`README.md` 能力矩阵补一行。
5. `.changeset/` 新增 minor 变更集。
