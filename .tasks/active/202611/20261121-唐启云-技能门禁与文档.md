# 技能门禁与文档

> 计划位置：第 2 个（共 2 个）；前置：20261121-唐启云-技能内容与打包；后继：无

## 背景

- 技能随包发布、按需读取，不存在安装、薄壳与漂移检测；门禁只需保证“打包带上技能、入口能被定位”，文档只需说清“什么时候需要读”。
- 需要避免把低频能力写成常驻流程，防止使用者与 AI 在日常生成时也被要求加载技能。

## 实施方案

1. **门禁**：`scripts/verify.mjs` 调用全局 toolkit——`toolkit skills lint skills/ --base <git 基准>` 校验命名、frontmatter、两处版本一致、篇幅、references 与“改动必须递增”；另保留本仓硬断言（打包包含 `skills/**`、`swagger2api skill` 输出路径存在且 `--print` 含 frontmatter）。CI 需能取到全局 toolkit（固定版本安装，下限 1.17.6，即包含 `skills lint` / `skills bump` 的发行版）；版本不足或取不到时降级为本仓硬断言并在 stderr 提示升级与安装，不静默通过。
2. **文档**：`docs/guide.md` 新增「AI 技能：什么时候需要」一节；`README.md` 与 `--help` 各露出一次 `skill` 命令——只在首次初始化配置、迁移旧配置、调整产物结构时读取；激活方式 `pnpm exec swagger2api skill --print`；日常生成、`--check`、验收不加载；不安装、不写项目文件、不维护状态。
3. **初始化流程**：文档给出最短路径——读技能 → 写最小 `swagger2api.json` → `--dry-run --json` 预览 → 生成 → 跑验收；并说明配置决策项（`mode` / `client` / `language` / `responses` / `query` / `pathPrefixIndex` / `tagRewrite`）；同时记录既有边界：生成物沿用 `// @ts-nocheck`，类型错误不进入下游检查。
4. **源仓库自举**：`AGENTS.md` 增加「本仓库能力自举」小节——开发时直接读仓库内 `skills/fxri-swagger2api/`，CLI 用 `node dist/cli.js` 直调本仓产物，改 `src/` 后先构建再验证。
5. **规范对齐**：技能结构与版本规则的机械真源是全局 `@fxri/toolkit` 的 `skills lint` / `skills bump`；本仓只保留自己的硬断言，不复制命名、篇幅与版本规则，避免两套口径。toolkit 在本仓的角色是开发期规范与工具来源，不是业务项目的运行时安装器。
6. **变更集**：patch 变更集，说明新增技能目录、定位命令与门禁。

## 影响范围

- `scripts/verify.mjs`（技能与定位命令断言）
- `docs/guide.md`、`README.md`、`AGENTS.md`
- `.changeset/`

## 验证方式

- `pnpm verify` 全量通过（含新增断言）。
- 故意删除技能目录、篡改版本或改坏 references 时门禁失败并指出位置。
- 文档中的激活与初始化命令可直接执行；日常生成路径不要求加载技能。
- 回滚：移除新增断言与文档章节，不影响生成链路。
