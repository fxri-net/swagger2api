# 能力清单命令与技能能力地图

> 计划位置：第 6 个（共 6 个）；前置：20261121-唐启云-移除产物清单改按横幅清理、20261121-唐启云-新增显式清理命令、20261121-唐启云-AI诊断能力与技能对齐、20261121-唐启云-拉取超时与版本标识；后继：无

## 背景

- 技能当前按「首次接入 / 旧配置迁移 / 产物结构」组织，AI 能完成具体动作，但**看不到工具全貌**：有哪些命令、各自解决什么问题、哪些是只读、边界在哪、失败后下一步是什么。
- 静态文档会随版本漂移；AI 需要一份「运行时自描述 + 静态能力地图」双通道，才能在不熟悉版本的情况下正确选命令。

## 实施方案

1. **重构 SKILL.md 为能力入口**（控制在约 200 行内，遵循渐进披露）：
   - frontmatter `description` 覆盖全部触发词：生成接口、校验产物、清理残留、迁移配置、审计布局、接口面基线、权限/配置排障，确保 AI 在对应场景都会加载；
   - 一句话定位与能力边界（能做什么 / 不做什么）；
   - **能力地图表**：`场景 → 命令（含稳定能力 ID）→ 产出 / 输出 → 只读 / 写入 / 破坏性 → 下一步`，并单列「不要用」场景（如不要用 clean 清理混放目录、不要手改生成物）；
   - 三步上手（生成 → 校验 → 按需清理）；
   - references 索引（按需加载，不整篇塞入）；
   - 安全约束（不手改生成物、破坏性命令需人工确认、禁止 AI 自行追加 `--yes`）。
2. **新增 references**：`capabilities.md`（逐命令用途、关键参数、只读/写入、退出码、产物形态、示例）、`troubleshooting.md`（症状 → 命令 → 预期输出，并附典型失败输出样例）、`recipes.md`（首次接入 / 多目标 / 离线迁移 / CI 接入 / 混放目录清理的完整配置与命令）。
3. **新增 `swagger2api capabilities --json`**：输出 `toolVersion`、`schemaVersion`、`commands[]`（能力 ID、名称、用途、只读标记、`destructive` 标记、关键参数、示例）、`configKeys[]`（类型、默认值、枚举、适用场景）、`exitCodes[]`、`skill`（入口、references 索引与各自用途、版本）；命令 ID 作为稳定契约，后续改名须保留别名；`swagger2api skill --json` 同步补 references 索引，供 AI 按需选择加载。
4. **漂移门禁**：以命令注册表为唯一真源，校验 `capabilities` 输出、技能能力地图与 docs 能力总览三处命令清单一致；每个命令必须有示例，示例以 `--help` / `--dry-run` 做冒烟，缺项、多出或示例失效即 `pnpm verify` 失败；技能写明「遇到未知更高 `schemaVersion` 时降级到 `--help` 与静态地图」，`troubleshooting` 的典型失败输出可做夹具防漂移。
5. 技能版本递增（能力级），docs 能力总览页与 README 从注册表生成或校验，避免三处各写一份；变更集标 patch（新增小命令）。

## 影响范围

- `skills/fxri-swagger2api/SKILL.md` 与 `references/{capabilities,troubleshooting,recipes}.md`、CLI 命令注册与 `capabilities` 命令、`scripts/verify.mjs` 漂移门禁、`docs/`、变更集。
- 不改生成与清理语义。

## 验证方式

- `pnpm test` 与 `pnpm build:debug` 后 `pnpm verify` 通过（含漂移门禁）。
- `toolkit skills lint` / `skills bump` 正常；`swagger2api capabilities --json` 可被 `JSON.parse`，且命令清单与 `--help` 一致。
- 按能力地图逐条走查：每个场景都能找到命令并得到预期输出。

## 回滚方案

还原技能结构与新增文档、移除 `capabilities` 命令与门禁、还原变更集。
