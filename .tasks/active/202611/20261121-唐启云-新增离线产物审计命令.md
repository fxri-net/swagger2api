# 新增离线产物审计命令

> 计划位置：第 2 个（共 3 个）；前置：20261121-唐启云-分桶口径文档与技能收敛；后继：20261121-唐启云-分片余量回填上一桶

## 背景

- `--check` 需要拿到 Swagger 文档重新生成后比对，文档不可用（服务下线、离线快照缺失）时无法校验产物布局。
- 最近一次离线产物升级中出现「1 / 7 / 9 / 1 条各占一个模块文件」的偏离，只能靠人工发现；缺一个不依赖文档、直接读产物的机械兜底。

## 实施方案

1. 新增只读命令 `swagger2api inspect --dir <产物目录> [--json] [--strict]`：
   - 逐模块文件统计：请求数（兼容 `this.http.request(`、`this.http.request<`（TS 泛型）、`this.request(` 三种形态）、类数、类名、文件字节数。
   - 判据取**解析后的生效配置**：非分片、非门面的独立模块文件请求数 < `minBucketRoutes` 告警；单文件请求数 > `maxRoutes` 告警；缺少 `index` / `client` / `types` 固定产物告警；`grouping.split: false` 时跳过布局判据（业务仓显式选择一组一文件，不得误报）。
   - 分片门面识别：0 个自有请求方法且构造函数为 `Object.assign(this, new XxxPartN(http), …)` 形态时判为正常；分片余量 < `minBucketRoutes` 只提示（交由「分片余量回填」任务消除）。
   - `--strict` 下存在告警即非 0 退出，供 CI 与技能调用；默认只输出报表。
2. `--check` 接入同一判据：生成到临时目录后，对「规划文件数与体量」给出与 `inspect` 一致的提示，不改变既有退出码语义（`--strict` 时才升级为失败）。
3. 文档与技能：`docs/cli.md` 补命令说明与示例；技能 `references/cli.md` 补一行；单测覆盖 JS / TS 两种产物、分片门面、小组独立文件、缺固定产物四类场景。
4. 变更集标 patch：对齐本仓 1.3.2 将新增命令（`surface`）按 patch 发布的先例；三项变更集均为 patch，同批发布 1.3.3。

## 影响范围

- 新增命令实现与单测（`src/`）、`docs/cli.md`、技能 `references/cli.md`、`docs/config.md`（分桶判据处引用）、变更集。
- 不改变默认生成行为；`--check` 仅在提示层复用判据。

## 验证方式

- 跑仓库聚合门禁 `pnpm verify`；新增单测全绿。
- 用现有业务产物目录做只读冒烟：能报出模块文件体量，并对已知的小组独立文件给出告警。
- `toolkit tasks check` error 与 warn 均为 0。
- 回滚：移除命令与文档段落、删除变更集。
