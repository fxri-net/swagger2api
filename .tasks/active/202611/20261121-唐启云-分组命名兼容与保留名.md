# 分组命名兼容与保留名

> 计划位置：第 2 个（共 4 个）；前置：20261121-唐启云-分组产物对外面兼容；后继：20261121-唐启云-产物清理安全与可复现

## 背景

- 单文件产物的模块属性名 = 首段路径经 camelCase 归一；已逐个核对下游 10 份产物的 541 个不同首段，全部与 `naming.ts` 的归一规则一致，所以 `strategy: ["path"], pathDepth: 0` 可以原样复现调用层级。
- 已发现的例外：某仓 base 产物同时存在 `/opt`（80 条）与 `/opt_`（3 条），归一后同名，单文件产物把两者合并到 `opt`；分组模式默认「重名各自独立并追加序号」，会产出 `opt2`，业务侧 `request.opt.optSettledApplicationPage*Post` 失效。
- 保留名缺口：现有保留集合只覆盖类名 / 文件名（`index`、`data-contracts`、`http-client`、Windows 设备名、`HttpClient` 等），不覆盖聚合成员属性名与手写适配文件名。组名撞 `instance` / `request` / `format` 会覆盖运行期成员；组名撞 `axios.ts` / `call.ts` / `base.ts` 等价文件会静默覆盖手写代码。
- 已确认的可见差异：分组模式默认 `preserveTags: true`，JSDoc 显示原始标签。下游两份产物现状共 494 条 `@tags` 为空，迁移后会恢复为原始标签；该差异经确认接受（仅注释层，无运行期与类型影响），迁移任务档记录为已知差异，不作为回归。

## 实施方案

1. 新增 `grouping.collapse`（布尔，默认 `false`）：折叠键相同的组在同一原始组名上合并、不追加序号，复现单文件产物的合并语义；命名表仍保证文件名、类名、属性名唯一。
2. 属性级保留名：`instance`、`request`、`setSecurityData`、`mergeRequestParams`、`stringifyFormItem`、`createFormData`、`securityData`、`securityWorker`、`secure`、`format`、`constructor`、`prototype`。命中时按既有「追加序号」规则改名，并在命名表 `reason` 中说明。
3. 参数守卫：`--replace-tags` / `-rt` 需要「匹配 + 替换」两个值。当前实现值不足时以空串替换，会把命中的标签清空（实证：下游两份产物共 494 条 JSDoc `@tags` 为空）。改为值不足时忽略该参数并在 stderr 告警「已忽略 —— 回落到保留原始标签」，不静默清空、也不阻断生成。
4. 测试：`grouping.test.ts` 覆盖 collapse 开 / 关与原始组名合并；`naming.test.ts` 覆盖属性级保留名与 `--replace-tags` 参数守卫；`scripts/verify.mjs` 用夹具断言 `--dry-run --json` 的命名表与产物一致。
5. 文档与变更集：`docs/config.md` 补 `grouping.collapse` 与保留名说明，`docs/cli.md` 补 `--replace-tags` 两个值语义与值不足时的降级告警，`docs/guide.md` 补合并示例；`.changeset/` 新增 patch 变更集。

手写适配文件的覆盖保护统一由第 3 个任务的生成清单承担，本任务不改动 `src/utils/modular.ts`。

## 影响范围

- `src/utils/naming.ts`、`src/utils/grouping.ts`、`src/index.ts`（标签参数守卫）、`src/__tests__/`
- 文档触达：docs/config.md、docs/guide.md、docs/cli.md、.changeset/

## 验证方式

- 夹具含 `/opt` 与 `/opt_`：`collapse: true` 时命名表只有 `opt`，`collapse: false` 时为 `opt` 与 `opt2`；两种产物的聚合挂载与命名表一致。
- 组名为 `instance` / `request`：属性自动改名且 `reason` 可见，聚合类运行期成员未被覆盖。
- `--replace-tags` 只给一个值时告警并忽略该参数（标签保持原样），给两个值时替换生效。
- `pnpm verify` 全量通过；单文件模式产物零差异。
- 本任务不发版；整批迁移验证通过后一次发版。
