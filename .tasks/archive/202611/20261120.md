## 背景

- 需求源头：下游姊妹仓的前端项目 swagger 文档极大。实测其生成产物为单文件 `index.js` 约 976 KB、`index.d.ts` 约 1.2 MB，导致 IDE / TS Server 卡顿、单次生成 diff 巨大、多人协作互相冲突。
- 当前形态：本工具已在单文件内按路径首段分组（`routes.combined` 渲染成 `class Api` 上的对象属性），业务侧以 `request.swagger.<组>.<方法>` 调用，出口只有一个。
- 目标：分组升级为「多文件 + 单一出口」，分组依据可配置、可交互建设、可复现；调用面形态保持不变。
- 与前置任务的关系：配置层（rc 三层、`--config` / `--profile`、`init` 向导、`config status`）由 20261113-唐启云-配置与交互式CLI 承担；本任务在 `grouping` 段之上实现分组逻辑与产物拆分。
- 分组口径：按 tag、按路径段、按自定义规则都是可选项，由用户在配置里选择，工具不替用户决定默认业务语义。

## 前置调研结论（已实测）

- `swagger-typescript-api@13.0.28` 的模块化模板上下文为 `route = { moduleName, routes }`；模板解析顺序为「自定义目录 → `templates/modular` → `templates/default`」，因此在本仓 `src/templates/modular/` 下新增同名模板即可覆盖，无需改依赖。
- 当前 `src/templates/api.ejs` 遍历全局 `routes.combined`，模块化时每个模块文件都会渲染全部接口（产物膨胀约 17 倍的成因）。
- 下游项目 `base/src/api/base/index.d.ts` 中 `class Api` 的成员是按路径首段生成的对象（`admin`、`home` 等），业务调用形如 `request.swagger.home.taxPdfRecalcPost`；拆分后必须保持该调用形态。
- 安全加固后的路径转义对正常路径零影响，模块名取自路径首段不受影响。
- 待执行时确认：13.0.28 是否提供 `config.fileNames.httpClient` / `dataContracts`（官方模块模板用到）；`generateApi` 返回值是否带文件清单（否则聚合入口改读输出目录）。

## 实施方案

### A. 分组策略（声明式 + 可交互建设）

1. 策略项：`tag`、`path`（路径段 + 深度）、`rules`（路径前缀 / 正则 / tag / operationId 匹配）、兜底组 `fallback`。
2. 优先级可配置，默认「显式规则 > tag > 路径段 > 兜底」；冲突在报表提示，不静默覆盖。
3. 阈值：低于 `minRoutes` 合并到父组或兜底组；超过 `maxRoutes` 按下一段路径或 tag 二次拆分。
4. 组名规范化：pascalCase、非法字符与 Windows 保留名检测、大小写冲突检测；与聚合类撞名（如 `Api`）加 `Module` 后缀。
5. 交互入口：`swagger2api grouping` 先输出统计（按 tag / 路径前缀的路由数与体积）→ 选择策略与优先级 → 合并小模块 / 拆分大模块 / 重命名 → 实时预览 → 写回配置的 `grouping` 段。

### B. 产物结构（多文件 + 单一出口）

1. `output.mode = grouped` 时输出：`index.ts`（聚合入口）、`data-contracts.ts`、`http-client.ts`、每模块一个文件。
2. 聚合入口保持现有调用形态：按组名挂载模块实例，业务侧仍是 `request.swagger.<组>.<方法>`；`export * from "./data-contracts"` 供类型引用。
3. 模块文件只含该组接口；`language = js` 时聚合入口产出 `index.js` + `index.d.ts`；`output.clean` 配合报表处理增删。

## 前置调研结论（已实测）

## 实施方案

### A. 配置模型（沿用同基地 rc 风格，语义化字段）

1. 配置文件与查找规则对齐同基地的 rc 惯例：项目层 `.swagger2apirc.json`（随 git 分发）、个人层 `.swagger2apirc.local.json`（默认不入库）、全局层 `~/.swagger2apirc.json`（跨项目偏好）；自工作目录向上查找最近的 rc 文件。
2. 结构按段组织、键名 camelCase，排障与文档统一用点号键路径（如 `output.mode`、`grouping.strategy`）：
   - `input`：`url` 或 `file`，以及请求头
   - `output`：`dir`、`mode`（`single` / `grouped`）、`name`、`clean`
   - `client`：`axios` / `fetch`；`language`：`ts` / `js`
   - `types`：`responses`、`unwrapData`、`extractParams`、`extractQuery` 等
   - `naming`：`pathPrefixIndex`、`convertGetToQuery`、`dropPathParams`、`tagRewrite` 等
   - `grouping`：预留给后继任务，本任务只做结构占位与透传
   - `profiles`：同一层 rc 内的多套命名预设（如按端区分的 admin / h5），不承担跨层或跨 app 职责
3. 合并与优先级：CLI 显式参数 > 环境变量 > 本地层 > 项目层 > 全局层 > 默认值；全局层到项目层按段整体覆盖，项目层到本地层按段内字段浅合并（数组整体替换）。
4. 多 app 仓库：仓库根目录的 rc 承载公共项，各 app 目录下的 rc 覆盖 `input` / `output`（向上查找天然叠加）；显式 `--config <path>` 只替换项目层，全局层与本地层照常叠加。
5. 预设选择：配置文件内的 `profiles` 通过 `--profile <name>` 选用，未指定时用 rc 的默认值；`--profile` 与 `--config` 可同时使用。
6. 环境变量覆盖：沿用同基地的 `FX_*` 风格，前缀定为 `FX_S2A_`；变量与目标键的对照表作为唯一真源，`config status` 与文档共用。
7. 旧配置共存：新 rc 优先；检测到旧配置文件时只读兼容并在 stderr 告警提示迁移，不静默合并两套配置。
8. `init` 写入受管的 `.gitignore` 片段（`*.swagger2apirc.local.json` 等），避免个人配置误提交；片段带稳定标识，重跑幂等。
9. 迁移：识别旧配置文件与旧的 npm script 参数，由 `init` 一次性转换；转换后旧调用方式仍可用，但文档主推配置 + 子命令。

# 生成链安全加固

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

- 运行时下限降到 node18 后，生成器钉在 `swagger-typescript-api@13.0.28`；官方安全修复只随 13.12.2+ 发布（要求 node20），因此 6 条生产依赖告警（5 high + 1 moderate）随 node18 线保留，已按用户确认记录风险。
- 用户要求在实际利用面上闭合这 6 条，且修复形式尽量与官方 13.12.2 一致，不接受自造开关式策略。

## 前置调研结论（已实测）

- 官方补丁由三部分组成（取自 13.12.2 包内 sourcemap 的原始源码）：
  1. `escapeJsStringLiteral(v) = JSON.stringify(v).slice(1, -1)`，套到 `CodeGenProcess` 的 `baseUrl` 与 `CodeGenConfig.Ts.StringValue`；
  2. `escapeJsTemplateLiteralStatic` / `escapeJsTemplateLiteralWithPathParams`，套到 `SchemaRoutes` 的 routeName 并保留已声明的 `${param}`；
  3. `util/remote-schema-fetch.ts`：与 spec 同源放行、其余仅公网 http(s)、拒绝 localhost 与私网 IPv4/v6（含 IPv4-mapped）、手动逐跳重定向（最多 5 跳）、`Authorization` 仅同源发送。
- 13.0.28 的 `Ts.StringValue` 在库内写死（`configuration.ts:240`），无法通过选项覆盖；远端拉取走库内 `request.download`，无法挂接全局 fetch。
- 13.0.28 不随包提供类型声明，`generateApi` 当前按 `any` 解析，既有 `Parameters<typeof generateApi>[0]` 约束已失效。
- 自有模板的注入出口：`procedure-call.ejs` 的 `path: \`<%~ path %>\`` 与 `"<%~ route.routeName.usage %>"`、`http-client.ejs` 的 `baseURL: "<%~ apiConfig.baseUrl %>"`、`api.ejs` 的 `@baseUrl ${server.url}`。
- lodash 两条已在 node18 任务内通过 overrides 4.18.1 消除，不在本任务范围。

## 实施方案

1. 新增 `src/utils/security/` 三个文件（`escape-js-string-literal.ts`、`escape-js-template-literal-with-path-params.ts`、`remote-schema-fetch.ts`），逐字移植官方实现，文件头注明出处与许可证。地址解析保留一个可注入入口（默认 `dns.lookup`），用于单测替换，便于离线覆盖「公网允许」分支；不引入请求超时，保持与官方一致，该限制记入文档。

## 前置调研结论（已实测）

- `swagger-typescript-api@13.13.0` engines 为 `>=20`，但其 17 个 dist 产物文件中无 `import.meta.dirname`、`toSorted`、`Object.groupBy`、`fs.glob`、`process.loadEnvFile`、`Promise.withResolvers`、`getBuiltinModule` 等 node20+ API 命中，`>=20` 属声明口径而非实测必然；其依赖（`c12`、`yummies`、`@biomejs/*`）均无 engines 限制。
- 13.13.0 用 biome WASM 格式化产物，`13.0.0` 用 prettier 3.0.0 格式化，且 13.13 新增 `content-type-accessors.ejs` 模板——**降级几乎必然改变生成产物的字节内容**，与「逐字节零差异」互斥。
- `13.0.0` 无 engines 限制，tarball 实测含 `modular`（28 处）、`moduleNameIndex`（7 处），模板上下文变量 `config.constants`、`routeName.usage`、`route.namespace`、`moduleName`、`modelTypes` 与 13.13 一致。
- `glob@14.0.3` 的 engines 虽写 `18 || 20 || >=22`，但依赖链 `path-scurry@3 → lru-cache@11`（engines `20 || >=22`）实际不支持 18；`glob@13.0.6/13.0.7` 经 `path-scurry@2 → lru-cache@11` 同样不支持；`glob@10.x` 虽可跑 18，但 `10.5.0` 已被官方标记 deprecated 并注明含公开漏洞（20260906 归档记录：当初升 glob 11→13 正是为消除该类告警）。
- 仓库内 `globSync` 仅在 `src/index.ts` 一处调用：`globSync(["./**/saconfig*.json"], { ignore: "node_modules/**" })`，可自实现替代。
- `src/` 未使用 node20+ API：`import.meta.dirname`、`toSorted`、`Object.groupBy`、`fs.glob`、`process.loadEnvFile`、`Promise.withResolvers` 均无命中；目录定位用自有 `getDirname()`。
- `tsup@9` engines 为 `^22.18 || ^24.11 || >=26`，node18 环境无法构建（本地 node20.20.2 亦不满足其 engines，属既存告警），故 node18 job 不得承担构建。
- `pnpm@10.34.4` engines 为 `>=18.12`，这是 18 线里工具链可安装的最低点，也是下限取 18.12.0 的直接依据。
