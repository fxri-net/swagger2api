# 修复变更集门禁在发版推送下的误报

## 背景

`scripts/verify.mjs` 的变更集一致性检查只比对 `baseline..HEAD` 净差异与当前 `.changeset/` 目录。发版提交会在同一次推送内消费并删除变更集，净差异里看不到新增项，导致 CI 误报「本次改动触及 src/ 或 docs/，须新增变更集」。本地以 `HEAD~1` 为基准时区间只覆盖发版提交，问题不暴露；CI 的推送基准覆盖内容提交与发版提交两段，必然触发。

## 实施方案

1. 变更集判定在现有「当前目录存在基准之外的新变更集」之外，增加「区间内曾被新增过」的条件：`git log --diff-filter=A --name-only --pretty=format: <baseline>..HEAD -- .changeset/`。
2. 只改判定口径，不放宽触发条件：触及 `src/` 或手写 `docs/` 仍必须有变更集。
3. 不改业务代码与文档内容。

## 影响范围

- `scripts/verify.mjs`：变更集检查增加区间内新增识别。
- `src/`：无触达，不涉及任何实现变更。
- `docs/` 与 `README.md`：无触达，门禁判定修正不改变对外描述。
- `AGENTS.md`：无触达，变更集质量门语义未变。

## 验证方式

- 用 CI 基准复现：取上一次推送提交作为 `CHANGESET_BASE_REF`，检查由失败转通过；
- 负例自测：临时改动 `src/` 文件并取 `HEAD` 为基准，仍须报「须新增变更集」，测完还原；
- `pnpm verify` 全绿；`toolkit tasks check` 无 error / warn；
- 推送后 GitHub / GitLab CI 转绿。

## 收尾动作

门禁判定修正属内部质量门调整，不改变对外能力；归档后随本仓验收与提交。
