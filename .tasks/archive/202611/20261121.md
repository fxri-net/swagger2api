# 分组命名通用化与报表补全

> 计划位置：第 1 个（共 3 个）；前置：无；后继：无

## 背景

- 分组输出的组名直接充当模块名：`src/utils/grouping.ts` 把组名写回接口 `tags`，交由生成器按 tag 产出文件名与类名；`src/utils/modular.ts` 再从产物文件名反推类名与聚合属性名。
- 组名来源是任意用户输入——tag、路径段、显式规则组名，字符集不受控。下游姊妹仓 8 份真实产物实测：860 个不同 tag，其中 234 个含 `/`、5 个以数字开头、2 个含空格、9 组在 NFKC 折叠后重名（半角/全角括号差异）、含顿号与引号、存在纯符号 tag（如 `[-controller]`）、最长 40 字。
- 现有实现的确定性缺陷：
  - `pascalCase` 按 `[^A-Za-z0-9]+` 切分并丢弃非 ASCII 段，中文组名得到空串，聚合入口会产出 `import {  } from "./…"` 这类非法代码；
  - 组名含 `/` 会被当作目录分隔符，产物写错位置；
  - 大小写、全半角折叠后相同的两个组名会互相覆盖文件；
  - 数字开头、TS 保留字、Windows 设备名（`con` / `aux` 等）、超长名均无处理；
  - 反向推导类名与模板内 `pascalCase` 各算一次，天然存在分叉风险。
- 现有冲突处理盘点：路由方法名重复交依赖库处理（模块内追加序号并告警）；聚合类名与 `Api` 撞名时改名为 `ApiModule`；`collectModules` 把 `index` / `data-contracts` / `http-client` / `*Route` 排除在聚合之外。**组级命名冲突没有任何处理**——两个原始组名经依赖折叠后同名会被静默合组，组名恰为 `index` 时模块文件会被聚合入口覆盖。
- 上一轮「模块化输出支持」方案里承诺的组名规范化、`--dry-run --json`、未命中规则清单、新增/删除文件报表均未实现，归档「实施偏差」也未记录，属于知识面缺口。

## 实施方案

1. **自建命名契约，不沿用依赖的命名推导**：新增 `src/utils/naming.ts`，`normalizeGroupName(raw)` 返回 `{ raw, key, fileName, className, property, reason, source }`。`key` 为 NFKC 归一 + 大小写折叠 + 去分隔符的结果，只用于碰撞检测与排序，不进入产物；`raw` 保留原值用于 `preserveTags` 与报表展示。`source` 标记 auto / manual / fallback。
2. **通用命名管线**（不针对单一语种）：
   - 文件名白名单 `[A-Za-z0-9_-]`，其余字符转为分隔并折叠；禁止 `.`、`..`、`/`、`\`、`:` 等路径字符；
   - 分词按 ASCII 词与 CJK/其他文字段分别成词，输出统一为 lowerCamel：词首字母大写、其余小写，禁止连续大写缩写；该形态对依赖的折叠稳定，兜底名同理取 `group<N>` 而非大写开头；
   - 首字符非法（数字、符号）时加固定前缀，类名必须是合法标识符；
   - TS 保留字与聚合属性名保留字（`new`、`delete`、`class` 等）加后缀；
   - Windows 设备名（`con`、`aux`、`nul`、`prn`、`com1-9`、`lpt1-9`）与产物保留名（`index`、`data-contracts`、`http-client`）加后缀；
   - 长度上限 64 字符，超出截断并追加稳定短哈希，保证同一输入多次生成一致；
   - 归一化后为空（纯符号、纯 emoji）时按原始名排序分配稳定组名 `group<N>`。
3. **命名表先行，产物按表渲染**：
   - 按原始组名以码点排序（不用 `localeCompare`，避免跨机器与跨 locale 结果漂移）→ 折叠键去重 → 不同原值同键时分配 `user2`、`user3` 形态后缀，并与已存在的同名组做二次碰撞检测，直到取到空闲名；
   - 折叠只用于判重，**不合并业务组**：半角/全角括号、仅大小写差异的组保持各自独立；
   - tags 写入命名表产出的模块名，原始标签继续经 `param.groupOriginalTags` 回填 JSDoc；
   - 模板类名不再由依赖的 `pascalCase(moduleName)` 决定，改由 `param` 传入命名表中的类名映射渲染；`api.ejs` 与 `route-types.ejs` 同源取用，聚合入口与模块文件同名；
   - 删除「从文件名反推类名」的逻辑；组名占用 `index` 等保留名时由命名表提前加后缀，避免聚合入口覆盖模块文件。
4. **产物校验门**：生成后按命名表核对实际文件名、类名、聚合属性名，任一不一致即报错并指出期望值与实际值；同时断言自有 slug 经依赖折叠后保持不变，把依赖行为从「隐含约束」变成「可检测契约」。若校验门被触发，或后续需要非 camelCase 的文件命名，则升级为「自有 grouped writer / 生成后重命名层」，不再迁就依赖；该升级不在本期实施。
5. **手工覆盖**：新增 `grouping.names`（原始组名 → 期望名），仍走同一管线校验；覆盖值不合规时报错并指出原始组名。该表属项目级配置，写在项目层 rc 并随仓库提交；rc 的段内浅合并意味着本地层写了 `names` 会整表替换项目层，文档须写明这一点，避免个人层误覆盖团队词表。
6. **与既有标签改写的顺序**：当前实现先分组、后执行 `--replace-tags` 的标签改写，分组模式下会把已写入的模块名再次改写（正则可整段命中并替换为空），导致组名丢失。方案要求先做标签改写再分组，分组模式下不再对模块名标签执行替换，并补一条组合用例。
7. **报表补全**：`--dry-run` 输出「原始名 → 文件 / 类 / 属性」映射、每项重命名原因与来源（auto / manual / fallback）、未命中规则清单、预计新增与删除文件；`--json` 输出结构化结果，供脚本消费。命中来源（规则 / tag / path / 兜底）由分组函数直接返回，报表不重复推断。
8. **表外文件处理**：聚合入口只挂载命名表中的模块；输出目录存在表外产物（改名后残留、手工文件）时列入报表并提示 `output.clean`，不静默混入聚合结果。
9. **测试**：合成样例覆盖斜杠、全角括号、中文、数字开头、保留字、Windows 设备名、超长、纯符号、大小写冲突九类；断言同一输入两次生成结果完全一致，且命名表与产物校验门在人为制造偏差时能报错。
10. **文档与变更集**：`docs/guide.md` 分组章节补命名规则与报表说明，`docs/cli.md` 补 `--dry-run` / `--json` 报表口径，`docs/config.md` 补 `grouping.names`；`.changeset/` 新增条目。
