# CI 补手动触发、条件化与补单元测试

批次：本仓本轮门禁与 CI 收敛（前置：无）

## 背景

1. 两个工作流只有 `push` / `pull_request`，平台丢事件时无手动补跑入口。
2. 聚合门禁每次本地运行都全量安装依赖并构建文档站，多数改动与二者无关。
3. 门禁没有任何单元测试环节：仓库有手写纯函数（URL 判定、命令行参数解析），却只靠类型检查与构建兜底，行为回归无网可依。

## 实施方案

1. `.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml` 各增加 `workflow_dispatch:`，附一行中文注释。
2. `scripts/verify.mjs`：新增 `--full` 与 CI 判定；安装按 lockfile 时间戳条件化；文档构建按 `docs/`、`README.md`、`package.json`、`pnpm-lock.yaml` 判触发；跳过时输出 `⊘` 与原因。
3. 引入最小测试闭环：
   - devDependencies 增加 `vitest`，`package.json` 增加 `test` 脚本；
   - 新增 `vitest.config.ts`，只收 `src/__tests__/**/*.test.ts`，**先不设覆盖率阈值**，避免为凑阈值写无效用例；
   - 新增 `src/__tests__/method.test.ts`（`isUrl`）与 `src/__tests__/common.test.ts`（`getParam` 家族，按模块加载快照 `process.argv` 的特性逐例重置模块注入参数）；
   - `scripts/verify.mjs` 在类型检查后加「单元测试」步骤。
4. 变更集：触及 `src/`（新增测试目录），按本仓门禁规则补 patch 变更集。
