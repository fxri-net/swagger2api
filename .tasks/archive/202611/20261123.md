# 接入方就地生成安全替换

> 计划位置：独立任务（共 1 个）；前置：无；后继：无

## 背景

为在发版前把接入方仓库的产物换成新版，验证脚本新增 `--in-place` 就地生成模式。首次实测时按「先删除产物目录 → 再拉取文档」执行，三个接入方的文档网关同时返回 503 / ECONNRESET，产物已删除而新产物未生成，只能从 git 恢复。

根因是就地模式缺少失败保护：删除与生成不是原子操作，拉取失败会留下空目录。

## 实施方案

1. `generateConfig` 增加就地模式分支：生成前把每个已存在的产物目录改名为同级的 `.s2a-backup-<时间戳>` 备份，而不是直接删除。
2. 生成与 `--check` 都成功时删除备份；任一步失败时移除本轮新增的产物目录并恢复备份。
3. 备份与恢复都使用同卷改名，避免复制大目录；备份名不进入产物识别，恢复后目录内容与原来逐字节一致。
4. 临时 worktree 模式保持原有「直接删除」行为，行为不变。
5. 帮助文案说明 `--in-place` 会写入真实工作区，且失败会自动恢复。

## 影响范围

- `scripts/business-validate.mjs`：就地生成分支与备份恢复。
- 不进入 npm 包，不改变生成行为，不需要变更集。
- 接入方仓库仅在生成成功时更新产物；失败时保持原状。

## 验证方式

- 成功路径：就地生成后产物为新版本，备份目录不残留。
- 失败路径：把配置指向不可达地址，生成失败后原产物完整恢复，目录内无残留新文件。
- `pnpm verify` 全部步骤通过。

## 回滚方案

移除备份恢复逻辑与 `--in-place` 分支，脚本回到只能在临时 worktree 内执行的状态。

## 完成情况

- `--in-place` 就地模式：生成前逐文件复制备份到系统临时目录，失败时清空内容并逐文件恢复，成功时删除备份。
- 目录改名改为文件级操作：真实仓库的产物目录可能被编辑器等进程占用，目录级改名会 EPERM。
- 成功后按旧横幅清理残留文件并移除空目录，手写文件与当前横幅文件保留。
- 实测：不可达地址失败后原产物逐文件恢复；本地夹具成功生成后旧文件被清理、无备份残留。
- 接入方 A 因文档网关 503 仍失败，但产物已完整恢复；D、E 已就地换成新产物且无旧横幅残留。
- 验证：`pnpm verify` 37 步全部通过。
