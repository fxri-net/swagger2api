# 配置模型 v2：单配置与文档列表

> 延续「多目标配置与批量校验」「配置文件命名与发现」（见 archive/202611/20261121.md）
> 计划位置：第 1 个（共 6 个）；前置：无；后继：20261123-唐启云-目标选择交互与-toolkit-对齐

## 背景

当前配置同时存在三套入口：根级扁平字段（`url` / `file` / `output` 字符串等）、`saconfig*.json` 递归扫描、`swagger2api.json` 的 `defaults` + `targets`。用户要求收敛为唯一一份 `swagger2api.json`，根上放公共配置、文档列表逐项覆盖，不再兼容 `saconfig`。

命名评估（不沿用现有名称）：

- 配置粒度保持现状：每个前端应用目录一份 `swagger2api.json`，与 `package.json`、产物同层；不同目录各自独立，不合并成仓库根一份。

- `defaults`：与工具内置默认值、三层配置的「默认层」混淆，语义不唯一；
- `targets`：来自构建系统，且与 `language.target`（输出语言）撞词，用户实际心智是「文档列表」；
- 推荐 `base` + `docs`：`base` 表示所有文档共享的基础配置，`docs` 直接对应「文档列表」。
- 文档项内把 `input` 收敛为 `source`（字符串即 URL 或文件路径，必要时用 `{ url | file, headers, timeout }`）；`client` / `language` 支持字符串简写，内部再归一为对象，避免 `language.target` 与文档列表撞词。

## 实施方案

1. 定义新 schema：根字段只允许 `base`、`docs`、`profiles`；`docs` 必填非空，每项必须有唯一 `id`，`source` 与 `output` 必填；`id` 只允许字母、数字、下划线、短横线，未知根字段报错并给迁移提示。`base` 可放共享的 `client` / `language` / `types` / `naming` / `grouping` 与 `output` 选项（`name` / `mode` / `prune` / `banner` / `typeCheck`），但不允许 `source` 与 `output.dir`；`output.name` 缺省为 `index`，不得包含路径分隔符与扩展名。`source` 为相对路径时按配置文件所在目录解析。
2. 合并规则：`base` 深度合并进每个文档项（对象递归、数组替换）；三层配置中全局层只允许 `base` / `profiles`，项目层定义 `docs`，本地层按 `id` 覆盖或追加文档项；`profiles` 在合并后、环境变量前应用。升级时不得删除 `swagger2api.local.json`。
3. 删除根级扁平归一与 `saconfig` 扫描：移除 `normalizeConfig` 的扁平分支、`scanConfigFiles`、`--config-scan`、`--config-all`、默认 `saconfig.json`、逗号多文件 `--config`；`--config` 只接受单个文件并保留。
4. 同步收窄跨配置冲突检查：只校验同一配置内文档项的输出目录互不包含；不再扫描同目录其他配置。
5. 输出目录与入口名：`output` 支持字符串（目录）或对象；字符串先归一为 `{ dir }`，再与 `base.output` 深度合并；`output.name` 优先级为文档项 > `base.output.name` > `index`；`id` 不参与类名，只用于选择与日志。
6. 更新 `config status`、`grouping`、`surface` 等命令对新结构的读取；`config status` 只读展示全部文档不提问，`grouping` / `surface` 在多文档时必须指定 `--target`，不弹交互。

# 接入方就地生成安全替换

> 计划位置：独立任务（共 1 个）；前置：无；后继：无

## 背景

为在发版前把接入方仓库的产物换成新版，验证脚本新增 `--in-place` 就地生成模式。首次实测时按「先删除产物目录 → 再拉取文档」执行，三个接入方的文档网关同时返回 503 / ECONNRESET，产物已删除而新产物未生成，只能从 git 恢复。

根因是就地模式缺少失败保护：删除与生成不是原子操作，拉取失败会留下空目录。

## 实施方案

1. `generateConfig` 增加就地模式分支：生成前把每个已存在的产物目录改名为同级的 `.s2a-backup-<时间戳>` 备份，而不是直接删除。
2. 生成与 `--check` 都成功时删除备份；任一步失败时移除本轮新增的产物目录并恢复备份。
3. 备份与恢复都使用同卷改名，避免复制大目录；备份名不进入产物识别，恢复后目录内容与原来逐字节一致。
4. 临时 worktree 模式保持原有「直接删除」行为，行为不变。
5. 帮助文案说明 `--in-place` 会写入真实工作区，且失败会自动恢复。

## 影响范围

- `scripts/business-validate.mjs`：就地生成分支与备份恢复。
- 不进入 npm 包，不改变生成行为，不需要变更集。
- 接入方仓库仅在生成成功时更新产物；失败时保持原状。

## 验证方式

- 成功路径：就地生成后产物为新版本，备份目录不残留。
- 失败路径：把配置指向不可达地址，生成失败后原产物完整恢复，目录内无残留新文件。
- `pnpm verify` 全部步骤通过。

## 回滚方案

移除备份恢复逻辑与 `--in-place` 分支，脚本回到只能在临时 worktree 内执行的状态。

## 完成情况

- `--in-place` 就地模式：生成前逐文件复制备份到系统临时目录，失败时清空内容并逐文件恢复，成功时删除备份。
- 目录改名改为文件级操作：真实仓库的产物目录可能被编辑器等进程占用，目录级改名会 EPERM。
- 成功后按旧横幅清理残留文件并移除空目录，手写文件与当前横幅文件保留。
- 实测：不可达地址失败后原产物逐文件恢复；本地夹具成功生成后旧文件被清理、无备份残留。
- 接入方 A 因文档网关 503 仍失败，但产物已完整恢复；D、E 已就地换成新产物且无旧横幅残留。
- 验证：`pnpm verify` 37 步全部通过。
