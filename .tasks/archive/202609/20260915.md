# 修正更新日志分组与类型前缀

## 背景

CHANGELOG.md 记录 1.0.0 至 1.2.7 共 24 个版本块，存在两类与 toolkit 现口径不符的历史遗留：

- 分组标题为旧口径（`### 🐛 补丁修复`），非现行 9 语义槽位标题（重大变更 / 新增功能 / 功能调整 / 优化改进 / 问题修复 / 文档更新 / 清理移除 / 依赖变更 / 其他变更）
- 多数条目无 `类型：` 前缀，个别条目把多种类型混写在同一条（如 1.2.7 把新增文档站与文档校对挤在一行、1.2.2 把文档类与优化类挤在一行）

`toolkit changelog format` 只归类 changesets 本次新写入的英文源标题块，按契约不追溯改写历史中文块，故历史块只能人工对齐。

## 实施步骤

1. 逐块取证：按版本 tag 区间取出对应提交的类型前缀（1.2.x 为 `优化：`/`修复：`/`文档：`/`修改：`/`清理：`/`新增：`，1.1.x 及更早为 `[新增]`/`[更新]`/`[修复]`），据实补 `类型：` 前缀并拆分混装条目，前缀以 git 记录为准，不按语义推断
2. 按语义槽位顺序（重大变更 → 新增功能 → 功能调整 → 优化改进 → 问题修复 → 文档更新 → 清理移除 → 依赖变更 → 其他变更）重排组，空组省略
3. 仅调整前缀与归组，不改写条目事实描述；版本号、发布日行、降序均不变
4. `toolkit changelog format` 复核，预期输出「无 CHANGELOG 需要更新」
5. `pnpm sync:changelog-doc` 重新生成 docs/changelog.md 镜像

## 判定说明

取证源口径：取承载条目内容的提交，发版仪式提交不作取证源；旧口径兜底标题（`### 🐛 补丁修复`）不承载语义，一律被 git 提交前缀覆盖。据此，以下 3 处保留原判定、不按提交标题前缀归一：

- **1.2.0 保留 `### ✨ 新增功能` + `新增：`**：承载提交 `4515804` 标题为 `优化：`，但同一提交把 package.json 的 version 由 1.1.13 改为 1.2.0（minor bump），提交正文 3 条均为「新增」句式，原块组标题亦已是 ✨。按类型→bump 表 `新增：`→minor 自洽；改取 `优化：`（patch）会固化「patch 级改动发 minor」的矛盾
- **1.2.3 保留 `### 📦 其他变更`**：区间唯一提交 `5078463 文档：发布 v1.2.3` 为发版仪式提交，`git show --stat` 显示零内容改动（仅版本号一行 + 归档 + CHANGELOG），不承载条目语义；`同步重发：` 不在 toolkit 前缀表内，规范兜底路径即 `other`
- **1.0.0 保留 `### 🚨 重大变更`**：root commit `01ff535 [新增]上传项目` 前缀为 `新增`，但首个版本按 semver / changesets 惯例即 major，`重大：首个版本…` 是发布方当时的正式口径
