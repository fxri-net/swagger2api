# 产物结构与验收

> 由 `../SKILL.md` 按需加载。产物由工具生成，不手改。

## 单文件模式

- 入口文件 `index.ts`（名称取 `output.name`），导出 API 类与全部契约。
- 客户端实例与请求参数类型由生成器内置，调用形态为 `api.<方法>()`。

## 分组模式

固定产物：

- `index.ts`：聚合入口，按命名空间挂载模块实例，共享同一个请求实例。
- `client.ts`：客户端底座。
- `types/index.ts`：契约出口；契约按业务文件拆到 `types/<业务文件>.ts`，共享或未归类进 `types/shared.ts`。
- 业务模块文件：按命名空间装箱；超大命名空间按子分类分片，由门面类合并实例与类型。

调用形态仍为 `api.<命名空间>.<方法>`；替换 `api.instance` 或调用 `setSecurityData` 会对所有组生效。

## 边界

- 生成物沿用 `// @ts-nocheck`：类型错误不进入下游检查，不要靠手改生成物修类型。
- 生成清单落在系统临时目录，不进入仓库；`--check` 据此判断缺失、多出与内容不一致。
- 旧版 `data-contracts.ts` / `http-client.ts` 不再生成，重新生成成功后会清理残留。
- 手写文件不在清单内时不会被清理；同名冲突会终止生成并提示。

## 验收

1. `swagger2api --check` 通过（产物与配置一致）。
2. 项目类型检查通过；需要更强约束时在项目侧写类型探针，不改生成物。
3. 抽查聚合入口：模块挂载、`export * from "./types"`、`export * from "./client"` 均存在。
