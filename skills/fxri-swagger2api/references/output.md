# 产物结构与验收

> 由 `../SKILL.md` 按需加载。产物由工具生成，不手改。

## 单文件模式

- 入口文件 `index.ts`（名称取 `output.name`），导出 API 类与全部契约。
- 客户端实例与请求参数类型由生成器内置，调用形态为 `api.<方法>()`。

## 分组模式

固定产物：

- `index.ts`：聚合入口，按命名空间挂载模块实例，共享同一个请求实例。
- `client.ts`：客户端底座。
- `types/index.ts`：契约出口；契约按业务文件拆到 `types/<业务文件>.ts`，共享或未归类进 `types/shared.ts`。
- 业务模块文件：命名空间只决定调用面，文件按体量装箱——总量 ≤ `minRoutes` 时只出一个模块文件；否则按命名空间码点序装箱，小于 `minBucketRoutes` 的桶并入相邻桶，单个命名空间超过 `maxRoutes` 才按子分类分片，尾片小于 `minBucketRoutes` 且回填后不超过 `maxRoutes` 时并入前一片，由门面类合并实例与类型。阈值默认值与覆写方式以 `docs/config.md` 为准，业务仓可用 `grouping.split` 覆写。

调用形态仍为 `api.<命名空间>.<方法>`；替换 `api.instance` 或调用 `setSecurityData` 会对所有组生效。

## 离线产物

文档不可用（服务下线、无快照）但产物需要升级时，按以下口径执行：

1. **布局以默认装箱为准**：小组并入相邻桶、超大命名空间才分片；不得按旧产物的组对象 1:1 落成模块文件。
2. **先录接口面基线**：用 `surface --requests-only` 或从旧产物逐条提取，改版后逐条比对，方法名、路径、参数形态与类型签名差异必须为 0。
3. **阈值不写进业务仓配置**：默认即可；确需不同布局才用 `grouping.split` 覆写。
4. **目录只含生成物时可给 `output.clean: true`**：文档恢复后整目录重建，避免手改残留。

## 边界

- 生成物默认沿用 `// @ts-nocheck`：类型错误不进入下游检查，不要靠手改生成物修类型；需要类型检查接管时配置 `typeCheck: "enforce"`，由工具统一剥离该行，`--check` 走同一处理。
- 产物归属靠生成横幅：生成物（含聚合入口、门面与契约）文件头带 `THIS FILE WAS GENERATED VIA SWAGGER-TYPESCRIPT-API`，手写文件不带；旧版（≤ 1.3.3）自写文件按「固定头 + 结构特征」兼容识别，升级后首个生成可直接覆盖，无需手工删文件。
- 清理与 `--check` 都以文件头判定：横幅只看前 1KB，旧版特征最多读前 4KB，不依赖持久状态。
- `output.prune`（分组默认开启）：按横幅清理本轮不再生成的文件；关闭时只报告多余产物、不删除。单文件模式不自动删除旧分组产物，只告警。
- 不要在生成目录里放手写文件、不要在自写文件里复用生成横幅；同一输出目录只允许一份配置（输出与本配置相同或嵌套的其他配置会被拒绝，退出码 2）。
- 模块共享请求器 `http` 为只读注入：运行期不可枚举、不可写；需要更换请求实例请走聚合入口的 `api.instance` 或 `setSecurityData`。
- 配置删掉某个 target 或目录搬家后，用 `swagger2api prune --dir <目录>` 清理废弃目录：默认只列、`--yes` 才删，只删识别为生成物的文件。
- 旧版 `data-contracts.ts` / `http-client.ts` 不再生成，重新生成成功后会清理残留。
- 手写文件不含横幅，不会被清理；同名冲突会终止生成并提示。

## 验收

1. `swagger2api --check` 通过（产物与配置一致）。
2. 项目类型检查通过；未开启 `typeCheck: "enforce"` 时需要更强约束就在项目侧写类型探针，不改生成物。
3. 抽查聚合入口：模块挂载、`export * from "./types"`、`export * from "./client"` 均存在。
